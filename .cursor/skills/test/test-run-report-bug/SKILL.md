## (2) Run the script

- The run entry is the same for both platforms: run the corresponding platform's `plan/debug.py` (its `scenarios(...)` registers **all features** to run for that platform); the pytest option **`--app-platform ios|android`** decides which platform's env/conftest to load (**do not use `PLATFORM=...` env var** — it has no effect in this project). Markers only use those registered in `tests/pytest.ini`, **do not write `-m ios`/`-m android`** (unregistered).
- pytest already configures `--alluredir allure-results` in `tests/pytest.ini` (`--clean-alluredir` each time). **Add `--junitxml`** to stably parse stats and failure details without relying on the allure binary.

**iOS (run all iOS features)**:

**Android (run all Android features)**:

**Custom**: replace the target file in the commands above with the user-specified `features/<JIRA_KEY>.feature` or add the user's `-k`/`-m` (markers must be registered in `pytest.ini`), with `--app-platform` set to the user's chosen platform.

## (3) Collect and analyze run results

**Collection sources (by priority)**:
1. `--junitxml` artifact (iOS: `tests/mobile/ios/log/last_run_report.xml`; Android: `tests/mobile/android/log/last_run_report.xml`): parse total / pass / fail / error / skip, and each testcase's `<failure>`/`<error>` message and traceback.
2. pytest terminal output (terminal file): failing step, `assert` context, pytest-bdd `Scenario`/`Step` location.
3. failure auto-screenshots under `screenshots/` (conftest saves on failure, named by case name) - **only as local human-investigation evidence, not written into the Confluence report body**.
4. raw results in `allure-results/` (view with `allure open` when finer granularity is needed, optional).

> When "All (iOS + Android)" is chosen, **collect and attribute per platform separately** (parse junitxml/terminal output separately), do not mix the two platforms into one stat.

**Root-cause analysis (this skill's core added value)**: for each failure/error, classify against the "common root cause" rules in the **test-script-memory** Confluence page, producing a three-part output:

- **Root cause**: one sentence on why it failed (e.g. "asserted the previous page's control before the transition settled, caught a stale frame").
- **Matched rule**: point to the corresponding rule in test-script-memory (by its content description, no longer numbered); against the "common root-cause cheat sheet" below.
- **Fix suggestion**: the minimal-change direction (which locator / wait strategy / assertion normalization to change), noting "code fix is taken by `test-debug-script`".

When the root cause cannot be judged from evidence, mark "root cause pending re-check" and state what evidence is still missing (e.g. "need the real device left on that page to verify elements"), **do not fabricate the root cause**.

### Common root-cause cheat sheet (against the test-script-memory Confluence page)

| Exception/symptom | Likely root cause | Rule |
|-----------|--------------|----------|
| `TimeoutException` stuck long on a page | implicit+explicit wait stacking / hard sleep / idle slowdown | the no-mixing-implicit-explicit-wait / no-hard-sleep / waitForIdleTimeout tuning / remove-redundant-waits rules |
| `NoSuchElementException` cannot locate | locator stale (with hash / deep xpath) / not scrolled into the visible area / name guessed wrong | the no-hashed-attributes / prefer-stable-semantic-selector / incremental-scroll / dump-before-guessing-name rules |
| `StaleElementReferenceException` / 'not present in current view' | the continuously-refreshing page element was rebuilt, reused an old reference | the use-reference-immediately / re-find-on-stale rule |
| `AssertionError` text unequal but looks identical | rendered spaces/format differences, assertion not normalized | the text-assertion normalization rule |
| `AssertionError` assertion fails on a success page / caught a stale frame | asserted the previous page's control before the transition settled (race) | the result-driven-confirm rule |
| Option/result matches a similar other one | used CONTAINS matching the longer, should BEGINSWITH/exact | the BEGINSWITH-over-CONTAINS rule |
| Tapped but did not navigate / click very slow | event not bound to the text/container or dragged down by waiting idle, should use coordinate mobile:tap | the rect-coordinate mobile:tap rule |
| Input box drops characters | one-shot send_keys too fast, should use per-character input | the per-character-input rule |
| `StepDefinitionNotFoundError` | the same step sentence uses different keywords but only @given is registered | the register-all-step-keywords rule |

## (4) Whole-page report structure (AI lays out the page accordingly - authored as Markdown, converted by the upload script; following the in-repo reference file `references/app_report_template.md`)

- **Top: ⚠️ error-cause summary (pinned, appears right after the AI declaration)**:
