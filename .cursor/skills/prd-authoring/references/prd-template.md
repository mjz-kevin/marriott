## 1. Business Overview〔必填〕

### 1.1 Business Background〔必填〕

- **现状问题**：{用户当前如何完成该任务，存在哪些障碍}
- **业务影响**：{对决策效率、数据可信度、协作成本的影响}
- **为什么现在做**：{业务驱动因素}

### 1.2 Purpose〔必填〕

1-3 个可量化目标，每条给出**当前值 → 目标值 → 度量方式**：

| # | 目标 | 当前值 | 目标值 | 度量方式 | 度量时间点 |
|---|------|--------|--------|----------|------------|

> 只写「提升效率」这类不可度量的目标会被 G4 打回。

### 1.3 Scope

| 端 | 需求范围 | 简要说明 | 优先级 |
|----|----------|----------|--------|
| {端1} | | | P1 / P2 |
| {端2} | | | P1 / P2 |

> 端列表按团队约定的拆分维度填写，不涉及的其他端写「本期不涉及」，不要删行。
> 优先级统一用 P1 / P2，P0 留给 Story 级。

### 2.4 Function Module Explanation〔必填〕

按 UI Section 逐一展开，每个模块一张表：

| UI Component | Element | Operation Logic | Data Requirement | Performance Requirement |
|--------------|---------|-----------------|------------------|-------------------------|
| {组件名} | {元素描述} | {用户操作 → 系统响应} | {所需字段、校验规则} | {响应时间、加载策略} |

> Performance Requirement 需要给出可量化口径（如「列表首屏 ≤ 1s（P95，4G）」），否则无法进入非功能验收。
